# 课表 · CourseTable

一个手机端课程表 App。前端是纯静态网页（HTML/CSS/JS），用 Capacitor 打包成安卓 APK。
所有数据保存在手机本地，不经过任何第三方服务器。

## 功能

| 功能 | 说明 | 离线 |
| --- | --- | --- |
| 周课表 | 周次切换、本周高亮、按周次过滤课程、点击空白格直接加课 | ✔ |
| **文件 / PDF 导入** | 教务导出的课表 PDF、xls / xlsx / csv，或粘贴课表页面 HTML | ✔ |
| 图片识别导入 | 相册选图 / 拍照 → 本地 OCR（模型已随包附带）或云端视觉大模型 | ✔ / AI 需联网 |
| 教务系统导入 | 填学号密码自动抓取。**新版正方的滑块验证码会使这条路不可用**，见下文 | ✘ |
| 手动维护 | 点选式添加课程，星期/节次/周次都是点格子，不用手输数字 | ✔ |
| 数据备份 | 导出 / 导入 JSON | ✔ |

各种导入都会先进入「待确认列表」，可以逐条改教师、地点、周次，勾选后再写入，不会直接覆盖已有课表。

**按成功率排序的建议**：教务能导出文件 → 走 PDF/Excel 导入；只能截图 → 图片识别；以上都不行 → 手动添加。教务自动抓取放在最后，因为它最依赖学校系统的实现方式。

## 最终产物在哪

**源码里没有 APK**，仓库里也不可能有——必须先在云端编译一次。完整链路：

```
本地源码（本目录）
   │  git push
   ▼
GitHub Actions 构建机（ubuntu-latest，自带 JDK 17 + Android SDK）
   │  ./gradlew assembleDebug
   ▼
构建机上的 android/app/build/outputs/apk/debug/app-debug.apk
   │  打包成 artifact
   ▼
GitHub 网页 → 那次运行记录 → 页面最下方 Artifacts → coursetable-debug.zip
   │  下载解压
   ▼
app-debug.apk  ← 你要的成品，传到手机安装
```

`android/app/build/outputs/apk/debug/app-debug.apk` 是**构建机上的路径**，在本地不存在。你拿到的地方是 GitHub 的 Artifacts 下载区。

## 目录结构

```
www/                     前端（Capacitor 的 webDir）
  index.html
  css/app.css
  js/store.js            数据模型 + localStorage 持久化
  js/bridge.js           原生 HTTP（绕过 CORS）、RSA 加密、文件读取
  js/parser.js           课表解析：周次/节次/地点/教师识别，表格与 OCR 词块还原
  js/import-jw.js        正方教务抓取流程
  js/import-ocr.js       Tesseract 本地 OCR + 视觉大模型
  js/import-file.js      pdf / xls / xlsx / csv / html 解析
  js/app.js              渲染与交互
  lib/                  离线资源（约 42 MB）
    tesseract.min.js / worker.min.js
    tesseract-core(.simd).wasm.js   OCR 的 wasm 核心，SIMD 与兼容两份
    chi_sim / eng.traineddata.gz    中英文识别模型
    pdf.min.js / pdf.worker.min.js  PDF 文字层提取
    xlsx.full.min.js                表格解析
capacitor.config.json
.github/workflows/       云端构建 APK
scripts/build-android.sh 本地构建 APK
```

> `lib/` 有 42 MB，是因为 OCR 的中文模型（19 MB）和英文模型（10 MB）都随包附带。
> 好处是**图片识别完全离线可用**，不再依赖国外 CDN 下载模型。代价是 APK 体积约 45 MB。

## 四种导入怎么用

### 1. 文件 / PDF 导入（推荐先试这条）

1. 在教务系统里把课表导出成 PDF 或 Excel，存到手机
2. 打开「导入 → 文件 / PDF 导入」，选择这个文件
3. 解析成功后进入「待确认列表」，核对后再写入

能读的格式：`.pdf` `.xls` `.xlsx` `.csv` `.html`。

**关于 PDF**

- 要求 PDF **带文字层**（教务系统直接导出的都是这种）。如果 PDF 是扫描件或纯图片，App 会明确提示你改用图片识别。
- PDF 里每一页会独立解析，最多读 12 页，多页课表会自动汇总。
- **设了打开密码的 PDF**：教务系统有时会给导出的 PDF 加密码。App 会提示你先用 PDF 阅读器去掉密码另存再导入。
- 如果提示「文件头不是 %PDF」，说明文件没下载完整或者根本不是 PDF，重新导出一次。
- 有些教务导出的其实是网页，只是后缀成了 `.pdf`。这种情况 App 会识别出来并提示你改用粘贴 HTML 的方式。

**另一条路（粘贴页面源码）**：在手机浏览器登录教务系统 → 进课表页面 → 长按全选复制 → 粘贴进 App 的输入框 → 点解析。

### 2. 图片识别导入

- **本地 OCR**：Tesseract.js 在手机上跑，先检测课表的表格线，再把识别出的词块按坐标投进格子，最后解析。**中英文模型已随 App 附带，完全离线可用**，不需要联网下载。
- **AI 识别**：在「设置」里填接口地址、模型名、API Key（OpenAI 兼容格式）。App 会把图片压缩后发给模型，让它直接返回结构化 JSON。准确率更高，需要联网。
- 建议用**清晰的截图**而不是拍照，截图没有畸变和阴影，识别率高很多。

### 3. 教务系统导入（成功率最不确定）

1. 打开「导入 → 正方教务系统导入」
2. 填教务地址（如 `https://jwgl.你的学校.edu.cn`）和系统版本（`/jwglxt` 新版或 `/jsxsd` 旧版）
3. 点「① 获取验证码」——验证码图片会出现在「验证码」输入框右侧
4. 照图把字符填进输入框（看不清就点「换一张」）
5. 填好学号、密码，点「② 登录并抓取」

**⚠️ 新版正方 / 正方云的滑块验证码：这条路会走不通**

新版正方教务（V9 及之后的「正方云」）把字符验证码换成了**滑块拼图**（登录页里是 `zfcaptchaLogin`、`zfdun` 这类标记）。
滑块必须由人拖动鼠标/手指完成，App 不做自动识别，所以**这类学校的自动登录无法实现**。

App 会主动读登录页判断类型：
- 检测到滑块 → 直接给出提示，让你改用 PDF / 图片导入，不会让你干等
- 检测到字符验证码 → 找出页面里真实的验证码地址再取图，比盲试路径准
- 两种都没有 → 按「无需验证码」继续登录

**其他注意事项**

- 这一路**必须在 APK 里使用**。浏览器的跨域（CORS）策略会直接拦掉请求。
- 不少学校要求连校园网或 VPN，校外访问连不上。
- 部分学校证书链不完整，安卓 WebView 会拒绝连接。
- 如果自动探测的接口路径不对，展开面板底部「高级：接口路径」手动改。验证码、公钥、课表三个接口都能单独指定。
- 我要如实说明：**这个模块没能在任何真实教务系统上实测过**，接口路径按公开流传的通用约定写成。能不能抓通取决于你们学校的部署。

### 4. 手动添加课程

点课表上的空白格，或在导入页点「手动添加课程」，都会打开同一个表单：

- **星期**：一排按钮点一下就选中
- **节次**：16 个格子。点第一格选起始节，再点一格选结束节（例如点 3 再点 4 就是第 3-4 节）；已经有区间时再点则重新开始
- **周次**：4 个常用快捷按钮（1-16 周 / 前 8 周 / 后 8 周 / 全学期），也可以手填
- **保存后再加一门**：连续录入时不用反复开面板，星期/节次/周次会保留，只清空课程名

从课表空白格进入时，星期和节次已经按你点的位置填好。

## 打包 APK

`android/` 目录已经生成好了（Capacitor 工程），所以云端和本地两条路都不需要再执行 `cap add android`。

### 路线 A：GitHub Actions 云端构建（不需要本机装 Android SDK）

1. 在 GitHub 网页上新建一个**空**仓库（不要勾 README、不要选 .gitignore，否则推送会冲突）
2. 一条命令完成推送（本地仓库已初始化并提交过，直接推即可）：

   ```bash
   bash scripts/push-to-github.sh https://github.com/<用户名>/<仓库名>.git
   ```

3. 推送本身就会自动触发一次构建（workflow 监听 main/master）。也可以手动触发：
   Actions 页面 → 左侧选 `Build Android APK` → 右上角 **Run workflow** → 选 main → 确认
4. 约 10 分钟后，点进那次运行记录，在页面最下方 **Artifacts** 区下载 `coursetable-debug`，
   解压得到 `app-debug.apk`，传到手机安装

不需要配任何密钥（Settings → Secrets 里什么都不用加），构建不依赖仓库密钥。

> `android/app/build/outputs/apk/debug/app-debug.apk` 是**构建成功后产物出现的位置**，源码里没有这个文件。
> 看到这个路径不等于 APK 已经存在——本机没有 JDK / Android SDK，从未编译过。

### 拿到 app-debug.apk 之后：装到手机上

**能不能直接用？能。** 它是 Gradle 打的 debug 包，已用 debug keystore 自动签名，装上去就能打开，不需要你再做签名。

安装步骤：

1. 把 APK 传到手机（USB 数据线拷贝、QQ「我的电脑」、邮件附件都行）
2. 手机上点开这个 APK
3. 系统问「是否允许安装未知应用」→ 给对应的来源开一次授权（Android 8+ 是按来源授权的，不是全局开关）
4. 若弹出「无法识别的应用 / Play 保护机制」提示 → 点「仍然安装」。debug 包没上架，这是正常提示

**几个真实的坑**

- **微信传 APK 会改后缀**（变成 `xxx.apk.1`），安卓认不出来装不了。传到手机后在文件管理器里把 `.1` 去掉，或者改用 QQ / USB 传。
- **要求 Android 6.0 以上**（`minSdkVersion 23`），2016 年后的机器基本都满足。
- **debug 包有时间限制吗？没有。** 但它是开发版，Android 15+ 可能在安装时多一步确认，不影响使用。

**装好之后**

- 课表、手动添加、文件导入、图片识别 —— 都能离线用（图片识别的本地 OCR 首次要联网下载十几 MB 的中文模型，之后离线可用）。
- **教务系统直连需要手机在校园网里**，或者先连学校 VPN。校外 4G/5G 大概率连不上教务服务器，这是学校网络策略，不是 App 的问题。
- 教务直连这条路我没法针对你们学校实测，抓不通就用图片或文件导入。

想改应用名、包名、图标，编辑 `capacitor.config.json` 里的 `appName` / `appId`，图标放在 `android/app/src/main/res/` 下。

## 先在电脑上看效果

```bash
cd www
python -m http.server 8123
```

然后浏览器打开 **http://127.0.0.1:8123** 。

几个注意点：

- 端口可以随便换。**8000 经常被别的程序占用**（占着的时候访问会返回 502），如果打不开就换一个，比如 `8123`、`8899`，启动后用命令行里显示的那个端口访问。
- Windows 如果提示找不到 python，用完整路径：
  `"C:/Users/<你的用户名>/.workbuddy/binaries/python/versions/3.13.12/python.exe" -m http.server 8123`
- 服务只监听本机（`127.0.0.1`），手机连同一个 WiFi 也访问不了。想在手机上看，把项目发布成一个在线链接更省事。
- 浏览器版无法直连教务系统，这是跨域策略导致的预期行为，不是故障。

## 自测

```bash
npm test
```

会依次跑四个测试（共 139 项）：

| 脚本 | 项数 | 覆盖内容 |
| --- | --- | --- |
| `scripts/selftest.js` | 44 | 周次 / 单元格 / 表格 / 教务 JSON / OCR 词块还原 / RSA / 存储 |
| `scripts/smoke-dom.js` | 42 | 页面初始化 + 手动添加的点选交互（选星期、点节次区间、保存后再加一门） |
| `scripts/smoke-jw.js` | 29 | 验证码两步流程、失败提示、滑块/字符验证码识别 |
| `scripts/smoke-pdf.js` | 24 | PDF 词块提取、表结构还原、逐字段校验 |

RSA 那几项用 Node 内置 crypto 生成真实密钥对再解密比对。PDF 那几项用真实 pdf.js 解析一份生成的课表 PDF，`scripts/test-timetable.pdf` 可用 `python scripts/make-test-pdf.py` 重新生成。

排查 PDF 解析问题时，`scripts/dump-pdfitems.js` 会把中间产物（词块、矩阵）打出来。

## 已知限制

- **新版正方的滑块验证码导致自动登录无法实现。** 滑块必须人工拖动，App 不做自动识别，这是有意为之而不是待办项。这类学校只能用文件 / PDF / 图片导入。
- 教务直连的成功率还取决于其他部署差异（路径、字段名、证书、校内网）。本项目做了自动探测 + 手动覆盖，但**不能保证所有学校都能抓通**，而且这个模块没有在任何真实教务系统上实测过。
- 本地 OCR 对合并单元格、斜线表头这类复杂排版的还原有限，识别后务必在确认列表里核对。
- PDF 导入要求文件带文字层；扫描件、纯图片导出的 PDF 请改用图片识别。设了打开密码的 PDF 需要先去密码。
- APK 体积约 45 MB，主要是随包附带的 OCR 中英文模型（29 MB）。如果更在意体积而不是离线可用，可以把 `www/lib/eng.traineddata.gz` 删掉，只留中文模型，能省 10 MB。
- 数据只存在本机，卸载 App 会清空，建议定期用「导出课表 JSON」备份。
- **没有在真机上跑过，也没有实际编译出 APK。** 测试都在 Node + jsdom 环境完成，真机表现未知。

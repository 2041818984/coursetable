# 课表 · CourseTable

一个手机端课程表 App。前端是纯静态网页（HTML/CSS/JS），用 Capacitor 打包成安卓 APK。
所有数据保存在手机本地，不经过任何第三方服务器。

## 功能

| 功能 | 说明 | 离线 |
| --- | --- | --- |
| 周课表 | 网格课表：左侧「节次 + 起止时间」时间轴、顶部日期行（月份 + 日期，今天高亮）、彩色课程卡片（课名 + `@地点`）；同一格有课撞车时并排显示；点标题跳周、左右滑动切周 | ✔ |
| **单双周** | 识别并显示单周 / 双周课，卡片底部带「单周」「双周」小标签；非本周的课整卡淡化并标「非本周」；手动添加有单周 / 双周快捷键 | ✔ |
| **文件 / PDF 导入** | 教务导出的课表 PDF、xls / xlsx / csv，或粘贴课表页面 HTML | ✔ |
| 图片识别导入 | 相册选图 / 拍照 → 本地 OCR（模型已随包附带，可取消、有超时）或云端视觉大模型（带连通性自检） | ✔ / AI 需联网 |
| 教务系统导入 | 填学号密码自动抓取。**已针对海南热带海洋学院（`zfjw.hntou.edu.cn`）实测校正**；滑块验证码的学校仍不可用，见下文 | ✘ |
| 手动维护 | 点选式添加课程，星期/节次/周次都是点格子，不用手输数字 | ✔ |
| 数据备份 | 导出 / 分享 / 导入 JSON | ✔ |

各种导入都会先进入「待确认列表」，可以逐条改教师、地点、周次，勾选后再写入，不会直接覆盖已有课表。

**按成功率排序的建议**：教务能导出文件 → 走 PDF/Excel 导入；只能截图 → 图片识别；以上都不行 → 手动添加。教务自动抓取放在最后，因为它最依赖学校系统的实现方式（登录、密码加密、课表接口已在海南热带海洋学院这台服务器上用真实账号跑通，别的学校仍需逐项探测）。

## 最终产物在哪

**源码里没有 APK**，仓库里也不可能有——必须先在云端编译一次。完整链路：

```
本地源码（本目录）
   │  git push
   ▼
GitHub Actions 构建机（ubuntu-latest，自带 JDK 17 + Android SDK）
   │  ./gradlew assembleDebug
   ▼
构建机上的 android/app/build/outputs/apk/debug/app-debug.apk
   │  打包成 artifact
   ▼
GitHub 网页 → 那次运行记录 → 页面最下方 Artifacts → coursetable-debug.zip
   │  下载解压
   ▼
app-debug.apk  ← 你要的成品，传到手机安装
```

`android/app/build/outputs/apk/debug/app-debug.apk` 是**构建机上的路径**，在本地不存在。你拿到的地方是 GitHub 的 Artifacts 下载区。

## 四种导入怎么用

### 1. 文件 / PDF 导入（推荐先试这条）

1. 在教务系统里把课表导出成 PDF 或 Excel，存到手机
2. 打开「导入 → 文件 / PDF 导入」，选择这个文件
3. 解析成功后进入「待确认列表」，核对后再写入

能读的格式：`.pdf` `.xls` `.xlsx` `.csv` `.html`。

**关于 PDF**

- 要求 PDF **带文字层**（教务系统直接导出的都是这种）。如果 PDF 是扫描件或纯图片，App 会明确提示你改用图片识别。
- PDF 里每一页会独立解析，最多读 12 页，多页课表会自动汇总。
- **设了打开密码的 PDF**：教务系统有时会给导出的 PDF 加密码。App 会提示你先用 PDF 阅读器去掉密码另存再导入。
- 如果提示「文件头不是 %PDF」，说明文件没下载完整或者根本不是 PDF，重新导出一次。
- 有些教务导出的其实是网页，只是后缀成了 `.pdf`。这种情况 App 会识别出来并提示你改用粘贴 HTML 的方式。

**另一条路（粘贴页面源码）**：在手机浏览器登录教务系统 → 进课表页面 → 长按全选复制 → 粘贴进 App 的输入框 → 点解析。

### 2. 图片识别导入

两种引擎，在弹层里切换：

**本地 OCR（离线）**

Tesseract.js 在手机上跑，**中英文模型已随 App 附带，完全离线可用**，不需要联网下载。

识别前会做两步预处理，这两步直接决定成败：

1. **检测并抹掉表格线**。课表的竖线会把表头「星期一」切成一个个孤立小块，tesseract 在孤立小块上很容易把 3 个汉字认成 `me`/`as`/`men`，整行表头就废了，所有课会堆到周一。抹线后表头能完整成行——实测关键词命中率从 0/14 提到 12/14。
2. **把「按字切词」粘回整段**。tesseract 把每个汉字当成一个独立词输出，「高等数学A」是 6 个词块。不粘回来，课程名会变成 `高 等 数 学 A`。粘合后表格里的每个格子都能还原成正确的一整段文字。

**关于「本地 OCR 一直卡死」——已经按下面四条改掉了**

原来的实现在 Android WebView 里有个致命问题：`Tesseract.recognize()` 内部自己 `createWorker`，一旦 worker 卡在加载 20MB 模型或 wasm 编译上，这个 Promise **既不成功也不失败**，界面就永远停在「识别中」，既等不到结果也取消不掉。现在：

| 改动 | 效果 |
| --- | --- |
| 自己 `createWorker` 拿到句柄 | 出问题能 `terminate()`，也能被用户取消 |
| 加了「取消识别」按钮 | 想停就停，不必杀进程 |
| 看门狗：两分半没有任何进展 | 主动停下来，并说清原因（图太大 / 内存不足） |
| **worker 复用** | 模型只加载一次，第二张图开始几乎立刻开跑 |
| 图片尺寸从「放大到长边 1800」改为「长边封顶 1500、最多放大 1.6 倍」 | 手机上计算量降下来，这是卡顿的主要来源 |

另外进度条旁边会显示已经等了多少秒，不会再出现「一动不动又不知道在干什么」的情况。

**AI 识别（更准，需要联网）**

在「设置 → AI 识别」里填**接口地址**（OpenAI 兼容，以 `/v1` 结尾即可，App 自己接 `/chat/completions`）、**模型名**、**API Key**。App 会把图片压缩后发给模型，让它直接返回结构化 JSON。

那个位置还有一个 **「测试连接」** 按钮。它会发一条最小请求，把服务端的原话直接摆出来 —— 遇到报错时，一眼就能分清是自己的配置问题还是服务端的问题。

App 对返回格式的兼容范围很宽：标准 OpenAI、Anthropic `content[]`、`output_text`，以及国内很多中转网关外面套的那层 `{code, message, data}`（真正的结构藏在 `data` 里）都能吃。如果网关把错误包在 HTTP 200 里返回（比如 `{"code":50507,"message":"Request failed: Unknown error","data":null}`），App 会把服务端原话和错误码一起显示出来，并给出排查方向，而不是甩一句「模型没有返回内容」。

**用哪种**

- 建议用**清晰的截图**而不是拍照，截图没有畸变和阴影，识别率高很多。
- 课表截图**要带可见的表格边框**，抹线那一步靠它定位；没有边框会退化成按坐标聚类，准确率明显下降。
- 本地 OCR 不花钱、不联网；AI 识别更准但依赖你的 API 服务。两条路都可以先试，识别结果都会进「待确认列表」，核对后再生效。

### 3. 教务系统导入

1. 打开「导入 → 正方教务系统导入」
2. 点「填入本校地址（海南热带海洋学院）」一键填好，或手填教务地址 + 系统版本（`/jwglxt` 新版或 `/jsxsd` 旧版）
3. 点「① 连接教务系统」——App 会打开登录页，读出这套系统要什么、不要什么
4. 填学号、密码，点「② 登录并抓取」

**学年 / 学期不用你填。** 早期版本让用户手填这两项，但正方的学期码是 `3 / 12 / 16`
（第一 / 二 / 三学期），不是直觉上的 `1 / 2 / 3`，填错就什么也抓不到。
现在 App 会**先打开课表页面，把里面 `#xnm` / `#xqm` 两个下拉框的选中项读出来**，
再用这个值去查课表——跟浏览器完全一样。抓完之后会把识别到的学年学期回填到界面上，
只有自动识别不准时才需要手填。

**先说一件最容易误会的事：不弹验证码是正常的**

海南热带海洋学院（`http://zfjw.hntou.edu.cn`）的登录页里写着 `dlsfbxyzm=0`，
意思是**平时登录根本不需要验证码**。验证码框要等你**连错 3 次**才会出现，
3 次之后账号还会被锁 3 分钟（`yzcskz=3`、`dlsbsdsj=3`，都是页面自己写明的）。

所以：点完「① 连接教务系统」没看到验证码，**不是 App 坏了，直接填学号密码点 ② 就行**。
也正因为只有 3 次机会，**App 故意不做自动重试**——密码错就停下来告诉你，让你先核对。

**这套系统实测确认的事实**（用真实账号跑通，见 `npm run check:real`）

| 项目 | 结论 |
| --- | --- |
| 登录页 | `/jwglxt/xtgl/login_slogin.html`，提交时要带 `?time=<毫秒>` |
| 密码 | 必须 RSA 加密：**PKCS#1 v1.5 填充，密文 base64**（`mmsfjm=1`） |
| 公钥 | `POST /jwglxt/xtgl/login_getPublicKey.html`，返回的 modulus 是 **base64**（不是 hex），1024 位 |
| 验证码图片 | `/jwglxt/kaptcha`（不是 `verifycode.servlet`） |
| **课表真实入口** | 页面 `/jwglxt/kbcx/xskbcx_cxXskbcxIndex.html?gnmkdm=N253508`（从主菜单里扒出来的），数据 `POST /jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` |
| **课表必带参数** | `xnm`（学年，如 `2026`）+ `xqm`（学期，`3`/`12`/`16`）+ `kzlx=ck`，**两个都不能空**：传空服务器直接回字面量 `null` |
| `/jwglxt/xskbcx/…` 那一支 | 本校**不存在**，返回 404「系统维护页面」 |
| 会话失效 | 未登录**且带 `X-Requested-With: XMLHttpRequest`** 时返回自定义状态码 **HTTP 901**；不带这个头则返回登录页 HTML |
| Cookie | 登录页同时下发 `JSESSIONID` 和 `route2`（负载均衡粘性），两个都要留住 |
| 服务器脾性 | 会间歇性不响应；**登录口还按 IP 限流**——短时间内连续登录多次后，即使密码完全正确也会被回「用户名或密码不正确」。App 把请求节流到每 900ms 一个并自动重试 |

**课表数据里「单双周」是明文写着的**

正方返回的每条课程记录里 `zcd` 字段形如 `2-16周(双)`、`1-15周(单)`、`5-8周,10-13周`。
早期解析器只认到 `2-16周` 就把 `(双)` 丢了，于是**单双周课被当成每周都上**；
`5-8周,10-13周` 这种多段写法还会丢掉后半段。现在解析器会把单双标记单独存成
`parity` 字段（1=单周 2=双周），课表格子的角标直接用它，不再靠「周次集合像不像奇偶周」去猜
（那个推断依赖学期总周数，而各校学期长短不一，必然猜错）。

**提交时会带上登录页里的全部隐藏字段**

正方的登录表单不只是 `yhm` / `mm` / `yzm`，还带 `csrftoken`、`language`、`xxdm`、
`mmsfjm` 等十几个字段。真实浏览器提交表单时会全部带上，只发三个字段有些部署会被拒。
现在 App 把登录页里的 `<input>` 整个抠出来原样提交。

注意：正方页面里的隐藏字段值**大多不带引号**（`value= 1`，等号后还有空格），
只按引号匹配的解析器会全部读成空——这一条由真实页面夹具兜住（`scripts/fixtures/hntou-login.html`）。

**⚠️ 新版正方 / 正方云的滑块验证码：这类学校仍然走不通**

部分新版正方把字符验证码换成了**滑块拼图**（登录页里有 `zfcaptchaLogin`、`zfdun` 标记）。
滑块必须由人拖动，App 不做自动识别，所以**这类学校的自动登录无法实现**，这是有意为之。
App 会主动读登录页判断：

- 检测到滑块 → 直接给提示，让你改用 PDF / 图片导入，不会让你干等
- 页面声明不要验证码（`dlsfbxyzm=0`）→ **跳过取图，省掉好几个请求**（该校服务器连发请求会不响应）
- 页面声明必须要验证码（`dlsfbxyzm=1`）→ 去取图，取图地址优先用页面里写明的，其次 `/jwglxt/kaptcha`
- 服务器回「验证码不正确」→ 此时才强制取一张图给你填

**其他注意事项**

- 这一路**必须在 APK 里使用**。浏览器的跨域（CORS）策略会直接拦掉请求。
- 校外访问请先连校园网或学校 VPN（实测该服务器公网可达，但校内服务不一定都开放）。
- 如果自动探测的接口路径不对，展开面板底部「高级：接口路径」手动改。
- 验证码、公钥、课表三个接口都能单独指定。
- **课表接口本身还没能端到端跑通**：`/jwglxt/kbcx/xskbcx_cxXsgrkb.html?gnmkdm=N2151` + `kzlx=ck`
  是按公开的 V9 接口规范写的，但未登录时服务器一律返回 901，所以**没法在不登录的情况下验证路径是否存在**。
  需要你拿真实账号跑一次才能确认。跑不通就走下面两条路。

### 4. 手动添加课程

点课表上的空白格，或在导入页点「手动添加课程」，都会打开同一个表单：

- **星期**：一排按钮点一下就选中
- **节次**：16 个格子。点第一格选起始节，再点一格选结束节（例如点 3 再点 4 就是第 3-4 节）；已经有区间时再点则重新开始
- **周次**：6 个快捷按钮（1-16 周 / 前 8 周 / 后 8 周 / 全学期 / 单周 / 双周），也可以手填
- **单双周**：选「单周」或「双周」后存下来的是对应的奇/偶数周列表，课表上会显示该课的「单」/「双」角标；切到第 4 周时单周课不会出现，切到第 3 周时双周课不会出现。顶部也会提示当前这一周是单周还是双周
- **保存后再加一门**：连续录入时不用反复开面板，星期/节次/周次会保留，只清空课程名

从课表空白格进入时，星期和节次已经按你点的位置填好。

## 打包 APK

`android/` 目录已经生成好了（Capacitor 工程），所以云端和本地两条路都不需要再执行 `cap add android`。

### 路线 A：GitHub Actions 云端构建（不需要本机装 Android SDK）

1. 在 GitHub 网页上新建一个**空**仓库（不要勾 README、不要选 .gitignore，否则推送会冲突）
2. 一条命令完成推送（本地仓库已初始化并提交过，直接推即可）：

   ```bash
   bash scripts/push-to-github.sh https://github.com/<用户名>/<仓库名>.git
   ```

3. 推送本身就会自动触发一次构建（workflow 监听 main/master）。也可以手动触发：
   Actions 页面 → 左侧选 `Build Android APK` → 右上角 **Run workflow** → 选 main → 确认
4. 约 10 分钟后，点进那次运行记录，在页面最下方 **Artifacts** 区下载 `coursetable-debug`，
   解压得到 `app-debug.apk`，传到手机安装

不需要配任何密钥（Settings → Secrets 里什么都不用加），构建不依赖仓库密钥。

> `android/app/build/outputs/apk/debug/app-debug.apk` 是**构建成功后产物出现的位置**，源码里没有这个文件。
> 看到这个路径不等于 APK 已经存在——本机没有 JDK / Android SDK，从未编译过。

### 拿到 app-debug.apk 之后：装到手机上

**能不能直接用？能。** 它是 Gradle 打的 debug 包，已用 debug keystore 自动签名，装上去就能打开，不需要你再做签名。

安装步骤：

1. 把 APK 传到手机（USB 数据线拷贝、QQ「我的电脑」、邮件附件都行）
2. 手机上点开这个 APK
3. 系统问「是否允许安装未知应用」→ 给对应的来源开一次授权（Android 8+ 是按来源授权的，不是全局开关）
4. 若弹出「无法识别的应用 / Play 保护机制」提示 → 点「仍然安装」。debug 包没上架，这是正常提示

**几个真实的坑**

- **微信传 APK 会改后缀**（变成 `xxx.apk.1`），安卓认不出来装不了。传到手机后在文件管理器里把 `.1` 去掉，或者改用 QQ / USB 传。
- **要求 Android 6.0 以上**（`minSdkVersion 23`），2016 年后的机器基本都满足。
- **debug 包有时间限制吗？没有。** 但它是开发版，Android 15+ 可能在安装时多一步确认，不影响使用。

**装好之后**

- 课表、手动添加、文件导入、图片识别 —— **全部离线可用**，图片识别的中英文模型也随包附带，首次识别不需要联网。
- **教务系统直连需要手机能访问到教务服务器**（校园网或学校 VPN；实测 `zfjw.hntou.edu.cn` 公网可达，但校内其他服务不一定）。
- 教务直连：登录、密码加密、学年学期自动识别、课表接口、单双周解析都已在海南热带海洋学院这台服务器上用真实账号跑通；抓不通时优先怀疑**登录口按 IP 限流**（等 5~10 分钟再试），其次改用图片或文件导入。

想改应用名、包名、图标，编辑 `capacitor.config.json` 里的 `appName` / `appId`，图标放在 `android/app/src/main/res/` 下。

## 已知限制

- **新版正方的滑块验证码导致自动登录无法实现。** 滑块必须人工拖动，App 不做自动识别，这是有意为之而不是待办项。这类学校只能用文件 / PDF / 图片导入。
- **登录口按 IP 限流。** 短时间内连续登录多次之后，**即使账号密码完全正确也会被回「用户名或密码不正确」**，等 5~10 分钟自行恢复。App 因此把请求节流到每 900ms 一个，并在密码错的提示里写明这一点。排查问题时别反复重试。
- **只有海南热带海洋学院这一台服务器是实测过的。** 该校的登录、公钥、验证码、学年学期下拉框、课表接口、单双周数据都用真实账号验证过（见 `npm run check:real`）。其余学校的部署差异（路径、字段名、证书、校内网）靠自动探测 + 手动覆盖兼容，不保证都能抓通。
- 该校服务器会间歇性不响应，App 已做节流（每 900ms 一个请求）+ 自动重试；但网络本身慢的话仍会等。
- 本地 OCR 对合并单元格、斜线表头这类复杂排版的还原有限；相近字形也会认错（实测里「王」会被认成「无」、「赵」认成「R」）。识别后务必在确认列表里核对。
- **本地 OCR 首次识别要加载约 20MB 中文模型**（解压后 44 MB），低端机上可能要十几秒到半分钟，进度条旁会显示已经等了多少秒。已加「取消识别」按钮和两分半的看门狗，不会再无声无息地卡住；内存紧张时请换更小的截图，或改用 AI 识别。
- 课表左侧时间轴用的是「设置 → 作息时间」里那份时间表（默认 08:00 起、每节 45 分钟）。**每所学校作息不同，第一次用请按自己学校的改一遍。**
- 图片导入依赖检测到表格线。若课表截图没有可见边框，会退化成按坐标聚类，准确率明显下降。
- PDF 导入要求文件带文字层；扫描件、纯图片导出的 PDF 请改用图片识别。设了打开密码的 PDF 需要先去密码。
- APK 体积约 45 MB，主要是随包附带的 OCR 中英文模型（29 MB）。如果更在意体积而不是离线可用，可以把 `www/lib/eng.traineddata.gz` 删掉，只留中文模型，能省 10 MB。
- 数据只存在本机，卸载 App 会清空，建议定期用「导出课表 JSON」备份。
- **没有在真机上跑过，也没有在本机编译出 APK。** 逻辑测试在 Node + jsdom 完成，APK 由 GitHub Actions 云端构建。

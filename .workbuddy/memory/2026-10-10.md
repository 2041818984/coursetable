# 2026-10-10

## 手机课程表 App（正方教务 + 图片识别导入）

用户需求：手机端课程表 App，支持从正方教务系统导入 + 图片识别导入。
用户选择：正方教务系统 / 安卓 APK / 两种识别引擎都做（本地 OCR + 云端视觉模型）。

### 交付结构
- 前端纯静态：`www/`（index.html + css + 7 个 js 模块 + lib 离线库）
- Capacitor 7（core 7.6.9 / app 7.1.2 / cli+android 7.6.9）打包安卓 APK
- `android/` 目录已生成（cap add android 成功），Manifest 已加 usesCleartextTraffic
- 云端构建：`.github/workflows/build-android.yml`；本地构建：`scripts/build-android.sh`

### 关键技术决策
- **绕过 CORS 靠 CapacitorHttp**，它内置于 `@capacitor/core`，不需要单独装 `@capacitor/http`
  （该包 latest 只有 0.0.2，是坑，已核实确认）。
- **Cookie 走 `CapacitorCookies`**（也在 core 里，但默认关闭，必须在 capacitor.config.json
  里 `plugins.CapacitorCookies.enabled = true`）。getCookies 返回 HttpCookieMap（名→值映射），
  不是 `{value:"a=1;b=2"}`，需自行拼串。
- **RSA 密码加密自己用 BigInt 实现**（modPow + PKCS#1 v1.5），支持 hex/base64url 公钥，
  提供 pkcs1 / raw 两种模式（各校部署不一致）。
- **本地 OCR 用表格线检测还原单元格**：对图片做行列暗像素投影找网格线，
  再把 Tesseract 词块按中心点投进格子，比纯坐标聚类准得多；检测不到线时回退聚类 + 块合并。

### 本机环境限制（重要）
- 本机**没有 Java / Android SDK / Gradle**，无法编译 APK → 走 GitHub Actions 云端构建。
- npm 直连会被中间证书拦截，必须加 `--strict-ssl=false`；curl 需 `-k`。

### 验证情况
- `node scripts/selftest.js`：44 项全通过（周次/单元格/表格/教务 JSON/OCR 词块/网格/RSA/存储）。
  RSA 用 Node crypto 真实密钥对交叉验证（私钥解密比对）。
- jsdom 冒烟测试 21 项通过、0 运行时错误（已跑完删除临时脚本）。

### 验证码交互改造（用户问"验证码怎么输"后重构）
- 原设计缺陷：验证码要**点同一个按钮两次**才出图，按钮文案恒定"登录并抓取"，
  用户完全看不出步骤 → 已拆成显式两步：`jwGetCode`（① 获取验证码）+ `jwLogin`（② 登录并抓取）。
- 新增 `#capBox` 占位容器：无图时显示"点下方①取图"，取到图显示图片，失败显示红色"取图失败"。
- 新增 `#jwWebHint`：非原生环境（!Bridge.isNative()）时显示橙色提示条，明说浏览器跨域会拦掉教务请求。
- **修复真实缺陷**：`detectCode` 失败会让 prepare 整体 reject → 无需验证码的学校永远进不去。
  现改为：prepare 先 `ping(base)` 探连通性（区分"地址错"与"该校无验证码"），
  验证码探测失败则降级为 `needCode:false` 继续；UI 收到 needCode=false 时隐藏验证码行。
- 新增 `scripts/smoke-jw.js`（jsdom，21 项全通过），已 cap sync 同步到 android 工程。
